把模糊的请求整理成可以着手执行的任务说明。

## 适用场景

当未回答的问题可能改变范围、成本、风险或成功标准时，使用 Clarify。它利用已有上下文，只追问重要的缺失信息，并在信息足够时停止提问。

结果会说明已确定的范围、已接受的假设、暂缓的问题和下一步。

## 安装

请先阅读技能说明。首次尝试请使用新的空白测试项目。运行命令前，检查目标目录和项目共享位置是否已有同名技能文件夹；任何更新都应单独决定。详见[通用安装指南](../../INSTALL.zh.md)。

```bash
npx skills add etsarkov/setupkit-ai --skill setupkit-clarify
```

选择目标助手，并将安装范围设为当前项目。确认前，请检查预选项、目标路径和最终摘要。部分助手共用 .agents/skills；同一项目中的其他助手也可能发现放在这里的文件。

npx会下载并运行安装程序。已验证的版本、安装方式和兼容性限制见通用安装指南。

## 示例

这些是说明性示例，并非实际运行记录。只有上下文缺少答案时，才需要提出相应问题。

### 自动化周报

**请求示例:**

```text
使用 setupkit-clarify：我们的周报占用了我太多时间。请帮我决定哪些部分适合自动化。
```

**可能提出的问题:**

- 周报的数据来自哪里？
- 谁使用周报？它应该帮助对方做出什么决定？
- 哪些步骤可以自动运行，哪些需要你审核？

**示意结果:** 形成边界明确的流程，包括输入、有用的输出、自动化步骤和人工审核点。这份任务说明不代表获准实施或发送周报。

### 明确产品发布帖的内容

**请求示例:**

```text
使用 setupkit-clarify：我想宣布我们的产品发布。请在写作前帮我明确帖子的内容。
```

**可能提出的问题:**

- 希望谁来阅读，他们应该理解什么？
- 你最想传达的一点是什么？
- 哪些结果或产品陈述有证据支持，你希望读者作出什么回应？

**示意结果:** 形成内容简报，说明读者、作者的核心观点、有依据的陈述和期望的回应。

## 限制

示例问题仅作说明。Clarify 不强制使用固定问卷，也不重复询问已有答案的问题。简单且足够明确的请求可以直接继续，无须追加问题。

技能仍受所选助手的权限和审批规则约束。它们不授予账户访问权，也不授权支出、发送、安装或发布。

只向所选助手提供你有权分享的材料。提供机密信息或个人信息前，请查阅该环境的数据处理条款。
