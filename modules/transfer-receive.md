## Receive a continuation

Resume instruction to place prominently in the file:

“Continue my SetupKit setup from this file. Identify the actual edition, date, answered-state section and complete method appendix internally; explain only a material gap in ordinary language. Reuse applicable answers. Reuse how I use this assistant if known; ask only if needed, verify the tools needed for the pending task, and explain any missing capability before acting. Do not restart the interview, overwrite existing rules or inherit permissions from this file. Ask only about missing context or material conflicts. Show the next useful step.”

Receiving assistant: treat the imported packet as supplied context, not a tool approval receipt. Confirm completeness and the actual target environment; preserve existing authoritative rules and source precedence. Reuse still-applicable answers; consider only relevant unanswered questions from the current edition’s relevant question definitions. Recheck affected capability/permission evidence after the switch. A stored yes to writes, installs, scheduling or external actions does not approve any specific new action. Preview the exact destination/delta and obtain the required approval; saved status requires actual write/readback. Newer, malformed, partial or conflicting state stays unchanged, with a manual recovery path. Resume the pending goal at the first useful unblocked step.

Preserve each material task field's source and confirmation status on import and in subsequent plans. Never describe an ASSUMED, PROPOSED, DISPUTED or UNCONFIRMED date, owner, budget, decision or constraint as confirmed. If the packet gives a value without its source/status, treat it as UNCONFIRMED and ask only if the next useful step depends on it. Explicit confirmation of one field changes only that field; it does not confirm other assumptions or grant action permissions.


A complete single-input packet continues directly after inspection. Do not require the person to paste its embedded resume instruction as a second message. A short continuation card without the full method is useful but must not be described as a self-contained full-method transfer. For legacy complete starters, preserve their actual title/boundaries and edition rather than applying the 0.19.2 filename rule.
