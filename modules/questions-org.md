### ORG-01 — ORG

Question: In which roles will you use AI?

Why: Examples include founder, product manager, researcher, writer, designer, developer, analyst, consultant, student, or personal assistant.

Effect / if deferred: Personalized workspace structure. Continue unrelated useful work.

### ORG-02 — ORG

Question: What is the main unit of work: product, project, client, topic, course, habit, or something else?

Why: This determines the top-level organization. Not everyone needs products, clients, and separate repositories.

Effect / if deferred: Top-level sections. Continue unrelated useful work.

### ORG-03 — ORG

Question: Which materials do you regularly create or receive?

Why: Examples include notes, sources, research, decisions, copy, images, code, tables, data, and final files.

Effect / if deferred: Routing rules. Continue unrelated useful work.

### ORG-04 — ORG

Question: Where are your materials now, and which tools do you use to find and read them?

Why: A new structure should respect existing tools rather than create a competing archive.

Effect / if deferred: Placement and migration plan. Continue unrelated useful work.

### ORG-05 — ORG

Question: Which materials are confirmed knowledge, and which are merely incoming or draft?

Why: Incoming material is not automatically a decision or fact.

Effect / if deferred: Promotion to the canonical knowledge base. Continue unrelated useful work.

### ORG-06 — ORG

Question: Do you work alone, or must part of the workspace be shared?

Why: This controls access, privacy, and the location of team instructions.

Effect / if deferred: Access and shared folders. Continue unrelated useful work.

### ORG-07 — ORG

Question: Do you create code or other files needing a separate version history?

Why: If yes, a Git repository may help. Normal notes and documents usually do not need one.

Effect / if deferred: `repos/` and Git setup. Continue unrelated useful work.

### ORG-08 — ORG

Question: Do you work with large or regularly updated datasets?

Why: If yes, separate originals, intermediate processing, final data, and exports.

Effect / if deferred: `datasets/`. Continue unrelated useful work.

### ORG-09 — ORG

Question: Do design sources, prototypes, or visual versions need independent storage?

Why: A design module helps when visual source files have their own lifecycle.

Effect / if deferred: `designs/`. Continue unrelated useful work.

### ORG-10 — ORG

Question: Which outcomes are ready for handoff, and what may be archived?

Why: Final results should be distinct from temporary work. Moving or archiving still requires preview and approval.

Effect / if deferred: `outputs/` and archive modules. Continue unrelated useful work.

### ORG-11 — ORG

Question: Do you need separate inboxes for people, applications, or AI agents?

Why: Separate inboxes keep unreviewed material away from accepted knowledge.

Effect / if deferred: Inbox structure and triage rules. Continue unrelated useful work.

### ORG-12 — ORG

Question: How often should inboxes and the structure be reviewed?

Why: Choose a realistic cadence; automatic moving is not implied.

Effect / if deferred: Maintenance cadence. Continue unrelated useful work.
