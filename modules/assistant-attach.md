## Connect another AI tool to an existing setup

Current first-release families are ChatGPT/Codex and Claude. Support both Claude to ChatGPT/Codex and ChatGPT/Codex to Claude, using the actual available surface. These are guidance targets, not verified compatibility for every plan or mode. Other families remain deferred; preserve their supplied answers and offer an honest manual or deferred route. This third entry is generic: later tools and a third or subsequent attachment reuse this process, not a two-tool toggle. Adding a tool does not remove the first one; changing a model alone does not necessarily require a new attachment.

Reuse the known goal, current tool and answers. Ask only what is missing: which tool to add, how the person uses it, and the work they want to continue. Use CORE-05 for actual usage; do not infer file access from a brand/model. Keep each asked question's why, effect and defer/decline fallback visible.

Read only the user-approved existing profile, continuation state, project rules and task-relevant sources. Do not search unrelated folders or accounts. If sources are missing or inaccessible, ask for selected input or offer a manual task; missing access is not proof of no setup. Conflicting authoritative profiles block dependent changes until resolved. Preserve relevant answers, goals, restrictions and canonical original paths; do not create another profile or rebuild folders by default.

Show a short reuse inventory and the smallest proposed target entry before any change. If the target has scoped local access, point it to the same canonical sources with a minimal tool-specific entry, preserving existing instructions and previewing the exact patch/path before an approved write. If it reads selected copies only, prepare the reviewed continuation packet described in the transfer-preview block; label source revision/date, original authority, copy status and how to refresh it manually. Preview exact selected data and destination before any separately approved provider transfer/upload. Do not copy secrets or the full conversation, invent memory sync, or silently migrate data to cloud storage. Local execution does not establish fully local processing or storage.

Check the target's actual capabilities and required action permissions. Desired access and past yes answers are not current grants. Recheck affected capability/permission evidence, including instructions that conflict with the target environment. Refused access or installation blocks only the dependent branch; continue an independent useful manual task. Uploaded copies are not live local synchronization; a generated download does not overwrite the original.

Verify attachment in a fresh target session: identify the actual profile revision, cite one applicable rule, retrieve a task-relevant source detail from available material, then complete one agreed small reversible useful task. Record actual evidence, exact source revision and target surface/date. A claim that sources were read is insufficient when a read can be observed. If a tool cannot access an original, state which supplied copy was used. No proof of all-source coverage follows from one check. Preserve the first tool's existing sources and entries.

Keep an attachment record with target identity/surface, entry and source references/revisions, access mode (`SHARED_LOCAL`, `SELECTED_COPY` or `MANUAL`), verified task/evidence, missing access, outstanding questions and next safe step. `VERIFIED`, `PARTIAL` and `UNVERIFIED` describe attachment evidence only, never interview question states. VERIFIED requires the agreed capability/result and source check; manual success cannot certify shared-folder access. On repeat, reuse this record and review only relevant delta, without duplicate profiles or entries. A third tool preserves earlier attachments. No implicit cross-provider transfer, write, installation, action approval or automatic synchronization follows from the record.
