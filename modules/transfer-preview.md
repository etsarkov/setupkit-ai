## Prepare one portable continuation file

After the person accepts, preview a minimal, readable SETUPKIT_CONTINUE.md and let them review or redact it before transferring to another environment/provider. Include:

- Kit edition, file revision date and handoff creation date (unknown if not observable); source and intended target assistant/usage mode.
- Goal, starting situation, working agreement, supplied sources and where original material lives; use only necessary path detail.
- Every material task date, owner, budget, decision and constraint with its original source and confirmation status beside the value. Keep the person's original relative date wording; any derived calendar date is ASSUMED / UNCONFIRMED until they explicitly confirm that field. Carry proposed or disputed values as such, including in summaries and task plans. Accepting a draft, choosing to keep it or approving a transfer does not confirm its individual fields. Missing labels in older context mean UNCONFIRMED, not confirmed.
- All supplied relevant answer summaries with stable question ID, question revision if known, active flag, state (OPEN, ANSWERED, DEFERRED, NOT_APPLICABLE or DECLINED), provenance and confirmation status. Preserve earlier inactive/conflicting answers with their status; do not invent missing answers or copy the full conversation.
- Active unanswered/deferred items, blocked or explicitly disabled actions, the pending task and its required capabilities; desired access kept separate from granted access.
- Actual last result, saved versus unsaved state, any verified destination, unresolved conflicts and next step. Do not claim a local save from a downloadable draft.
- The transfer-receive instructions and a clearly separated verbatim full current COMPLETE.md method appendix, including its question bank, so one file can carry both the method and the answered state. Include only text actually available; never reconstruct a missing section.

Keep secrets, tokens, passwords, credentials, unnecessary private material and permission grants out. The person must approve the destination/content before a write. If creating a downloadable file is supported, provide it and name exactly what was produced. Otherwise provide complete copyable text. If output limits prevent one file, offer explicitly numbered parts and an inventory/completeness check; never call a partial packet complete. The user's approved private original remains canonical when applicable; do not silently create a competing profile. Nothing is uploaded to SetupKit.
